# GOALASSO · מאמן כדורגל

Hebrew (RTL), mobile-first football management game. Single-file web build.

## Layout
- `src/index.html` — document shell (doctype, meta, manifest/icons, markup) with `__CSS__` / `__JS__` placeholders.
- `src/styles/NN-*.css` — stylesheets, concatenated in file-name order. Later files override earlier ones: `07-theme-direction-a.css` is the current theme, `08-cinematic-lineup.css` the lineup screen (the stadium photo `assets/lineup-arena.*` with round portraits and a name plate — rating, name, fitness as the ring colour — placed by `pitchProject`/`ARENA` in `36-views.js`; `12-formation-board.css` keeps the beginner mode's formation board on `assets/lineup-reference-stadium.jpg`), `09-phone-readability.css` the mobile overrides, `10-market.css` the transfer-market search/filters.
- `src/js/NN-*.js` — the game, one shared script scope (no ES modules). Load order = numeric prefix: `01-data` → `02-util` → `03-players` → … → `36-views` → `36b-broadcast` … `36h-notify` → `37-live` → `38-boot`. Function declarations are hoisted, so views may call engine code; `const`/`let` must be declared in an earlier file than their first top-level use. Put new code in the file that owns the subject (engine in `07-engine.js`, money in `18-week-flow.js`, screens in `36-views.js`, persistence in `22-save.js`).
- `src/build.py` — `python3 -I src/build.py` → writes `ligat-haal-manager.html` at the repo root (concatenates the modules, embeds data, splash, logo and the portrait manifest). Placeholders `__CLUBS_JSON__`, `__EURO_JSON__`, `__DATA_META__`, `__SPLASH_IMG__`, `__LOGO_IMG__`, `__PLAYER_VISUALS__` are filled by the build.
- `data/*.json` — Israeli club squads; `data/euro/*.json` — European squads.
- `assets/` — media loaded at runtime by relative path (intro/signing videos, lineup stadium, newspaper photos, trophy moments). They must sit next to the built HTML.
- `tests/*.test.js` — jsdom suites (`npm install`, `npm run build`, `npm test`). A suite passes when its last line shows `errors []` / `errs []`. `idb-save.test.js` runs the IndexedDB path on `fake-indexeddb`; `window.ILM.ready` resolves after boot and `window.ILM.whenSaved()` after the pending write.
- Player portraits: `scripts/build-portraits.py` turns the verified source photos (`data/visuals/source-photos/`) into canonical 240×300 transparent WebP cut-outs in `assets/facepacks/` (schema 2) and records each result in `data/visuals/portrait-audit.json`; manual decisions live in `data/visuals/portrait-overrides.json`; `scripts/portrait-report.py` writes `docs/portrait-audit.md`. The game never crops faces at runtime (`portraitGroup` / `cinematicPlayerHTML` in `36-views.js`); anything not `ok` renders the designed club-kit monogram fallback. Never assign a face to a different player, and never match European players to Israeli faces by name.
- European portraits (real squads in `data/euro/`): `.github/workflows/fetch-portraits.yml` (manual; runs `scripts/fetch-commons-portraits.py`, identifies each player on Wikidata by exact name + club / birth year and downloads freely licensed Commons candidates with author/licence) → branch `portrait-sources`. Locally, `scripts/import-commons-portraits.py --sources <portrait-sources checkout> --clubs …` picks the first candidate the pipeline accepts in strict mode (a player keeps the face he has and recorded refusals are not measured again unless `--fresh`; decisions are cached per file and pipeline content in `<sources>/.import-cache.json`) and writes `data/visuals/source-photos/eu-<club>.json` (git-ignored: the originals live on `portrait-sources`) + `data/visuals/euro-players.json` (identity, source, licence, credit, fallback reasons); then `build-portraits.py --only eu-<club>,…` and `--skin-only`. Files rejected on visual review go in `data/visuals/portrait-reject-files.json`. Files the strict checks refuse but a visual review accepts (frontal, single subject, verified identity) go in `data/visuals/portrait-accept-files.json`; a candidate with an attribution licence and no recorded author is never used. A second pass for players still without a face (`fetch-portraits.yml` input `more=true` → `--more`): only the players listed as unresolved, the whole Commons category (200 files), sub-categories and full-text search, players the first pass could not identify are asked again (`identify`, which also accepts the one footballer of that name whose English article lists this club in its infobox, `infobox_clubs`), files already judged skipped, the new ones ranked by `portrait_score` (the file's own "depicts" statements, the name in the file name, portrait words against group/match words, shape) and the best eight downloaded as `…-m<k>.jpg` with `depicts` recorded; the import treats a file that depicts this player and nobody else like his Wikidata image. A file nobody names (an unnamed file of his category, a name-search hit) is used only when its single face is the face of one of his named pictures (`FaceMatch` in the import: OpenCV SFace, cosine ≥ `FM_MIN` 0.55 for a file of his own category, `FM_MIN_SEARCH` 0.60 for a name-search hit, never a file whose "depicts" names somebody else; a category file whose name names somebody else as well (`two_names`: another name right before his, or "A and B") needs the face match too; the model is not in the repo, `$SFACE` or `~/.u2net/sface.onnx`, without it nothing is matched); the evidence is written to the face's `reviewed` field and `--review DIR` saves reference and candidate side by side for the visual check. Squads named in Hebrew (Leumit) are identified by Hebrew label/alias/article title + the club on the item (`identify_hebrew`, no birth-year fallback). Faces resolve by club + English name only; credits ship in each pack and show on the player profile and under מידע → תמונות שחקנים.
- Real squads from Wikipedia (clubs in `data/config/world-clubs-wiki.json`): `.github/workflows/fetch-squads.yml` (manual; `scripts/fetch-wikidata-squads.py`: the article's current-squad templates, else the club's squad template with positions from Wikidata, Hebrew Wikipedia for the Leumit clubs; a player "on loan from" another club is a squad member) → branch `squad-sources` (`squads/<key>.json`, `_debug/` dumps for pages that did not parse). Locally `scripts/import-squads.py --sources <checkout>/squads --clubs …` writes `data/euro/<key>.json` (one factor per squad puts its best-14 rating on the club's strength + 1) and lists the players as unresolved in `euro-players.json`; `--merge` adds players a newer fetch lists (nobody is removed), `--sync-identities` afterwards, `--rescale` re-applies the value rule. Portrait candidates for new or changed squads are fetched from a work branch (`ref=squads-wip`) so nothing half-done deploys. Only one portrait import may run at a time (it rewrites `euro-players.json` as a whole).
- Real players only: the config groups are `world` (market clubs), `euro` (European opponents of `EURO_CLUBS`) and `leumit`; a club with no squad on Wikipedia is removed from the game rather than shown with invented players (Young Africans, Petrocub). `inventedPlayer(p)` (no English name, no Israeli identity) marks generator players: they are never listed on the market, in the search or as free agents, the free-agent list starts empty, and real squads are never padded. Invented players remain only where the game needs bodies and has no names: academy prospects and season-end top-ups of a club with no youth side in the data (or whose list is used up). Hebrew spellings for second-tier players that the sources give in Latin letters live in `data/config/leumit-names-he.json` (transliterations; `import-squads.py --clubs all --names`). Save v12 (`migrateRealOnly`) applies all of this to existing careers.
- Liga Alef and youth (`scripts/import-ifa-rosters.py --xlsx <workbook>`, the federation's registered squads; the workbook is not kept in the repo): `data/euro/a_<key>.json` (35 clubs of both districts, `league: alef_north|alef_south`, city and approximate shirt colours; the build lists them in `RAW_ALEF` = `ALEF_POOL`, so the two clubs that come up each season are real clubs with their real squads) and `data/config/youth-squads.json` (senior club → names of its youth side, embedded as `RAW_YOUTH`). The source has names only: for Liga Alef the position and value are dealt by the import from the player's id (`generated` in each file), ages are drawn by the game; youth are stored as names only (no ids, links, dates or photos, and masked names are skipped). In `03-players.js`: `makePlayer` tags generator players `gen:1` (`generatedPlayer(p)` also recognises them in older saves), `giveRealName(p,club,taken)` gives a prospect a name of his club's youth side once per career (`G.yused`) and never while that name is already in the game, with `visualId:null` so no portrait is matched by name; `realizeYouth()` (new career, season end) and `topUpPlayer` (season-end top-ups: a graduate aged 18–20) use it. Federation photos are not used: they are not freely licensed and a third of them show minors. Save v14 (`migrateAlefYouth`): generated squads of promoted clubs become the registered ones and the other clubs' generated prospects get real names; the manager's own club is untouched. `tests/alef-youth.test.js` covers it.
- First person: the 3D highlights have two extra cameras (`עיני הבועט`, `עיני השוער` in `assets/demo3d/live.js`: the camera sits at the player's eyes, his own body hidden). Coach's-eye video clips (press conference, tunnel, dressing room, trophy…) are described in `data/config/video-prompts.json` and generated by `.github/workflows/grok-video.yml` (manual; `scripts/grok-video.py`, xAI video API, repository secret `XAI_API_KEY`) onto the `video-sources` branch for review; no real people, badges or readable text in the prompts.
- Portrait review: `scripts/check-portraits.py [--sheets DIR]` measures every shipped cut-out (frame, eye line, face size, hair against the top edge, sides, opacity, sharpness). The import (`import-commons-portraits.py`) writes the accepted cut-out into the pack itself (cache in `<sources>/.import-built`), so `build-portraits.py --only …` is only needed for faces decided by an older cache. Round avatars (`.rt-face`, `.bc-face`) are framed by `faceFrameStyle(p)`: the window starts 12 px above the player's own hair line (`PLAYER_VISUALS.faces[].top`, from the audit's `hairTop`), never lower than 20 px. A cut-out without shoulders (`bust:0`) gets a drawn soft neck and collar in `portraitGroup`.
- Broadcast package (`36b-broadcast.js`, `14-broadcast.css`; presentation only, reads `M` and its events): `#bcLayer` inside the arena (a flat strip when match graphics are off). `bcEvent` queues one plate per key event (goal, card, substitution, injury, big save) with the player's face; `bcScore` pulses the score bug and marks sent-off players; `bcSlate(M,h,a,'half'|'full')` is the statistics board at the breaks (score, scorers, possession, shots, xG, man of the match). The app header (`#top`) is hidden while the live screen is up; `render()` brings it back. `tests/broadcast.test.js` covers it.
- World transfer market (`11-market.js`, `viewWorld`; Israel tab `viewMarket` in `36-views.js`): clubs with data in `data/euro` show their full squad (`fillRealWorldSquad`, idempotent: a player is recognised by English name + origin club `p.from`, so re-valued data never duplicates him; `WORLD_SQUAD_V` marks the data generation, and a squad from an older generation that sits 3+ points under the club's strength is lifted back to it; run by save migrations v9 and v11); real squads are never padded with invented players; the 11 most valuable players are listed as in the squad but not for sale (`p.nfs`): talks open only with an exceptional offer (asking price ×2.4 at tier-1 clubs, ×1.9 elsewhere, no haggling below it, 2 rounds of patience). Every market club has a real squad (the generated 7-player list is only the fallback path for a club whose data is missing). "ליגיונרים ישראלים" = real players whose data nationality is Israel at clubs outside Israel. Name search gives live suggestions from 2 letters (Hebrew/English, accents and Hebrew final letters ignored) across Israel and all world leagues. `tests/world-market.test.js` covers it; `.github/workflows/live-check.yml` (manual) runs `scripts/live-market-check.js` on the deployed site at iPhone size and pushes screenshots + report.json to the `live-check` branch; the report's `play` section covers live play on the deployed build (shout bar, one penalty we kick and one we keep goal for, both through the overlay, with the view that drew them, career card, a quick-tournament draft and the return to the career); the script owns every penalty of its match, so a penalty the engine awards by itself is decided automatically there, and it reports `gpu3d` (would the game pick the 3D view on that browser by itself) and `slow3d` (the frame-rate verdict after the first kick). The `beginner` section opens `beginner.html` beside the page: score numbers on their own team's side, the carrier's name on the pitch, ratings of both sides in the result dialog. The `pcup` section opens אלוף הפנדלים on the beginner page (lobby, a shoot-out against the computer) and plays two kicks between two browser contexts in one room over the real Realtime channel (`online.same`: both saw the same kicks). Each build carries `<meta name="goalasso-build">` (content hash) so the check can tell which build is live.
- Match engine (`07-engine.js`): three units per side from the XI (`unitStrength`: gk/def/mid/att by slot, roles blur them; captain, boosts, chemistry, mental programme and the training plan's `trainBonus` apply to all units). `expGoals` = attack vs the opposing defence on a convex curve (~0.08 goals per rating point, capped), scaled by midfield edge, plus home advantage, mentality, `tacticAdj`, and an 8-minute momentum after goals. Above `XG_SOFT` (3.2) expected goals for the two sides together only `XG_KEEP` (a fifth) of the surplus is kept, in proportion for both (tier-1 tactics, roles and forwards rated far above the keepers they face stacked up to 4.5 goals a match between Europe's richest clubs; now about 3.6, the Israeli league unchanged at 2.7); a touchline shout is left whole. Each minute a side may create a chance (rate ∝ expected goals); `chanceSpot` by style gives a location and real xG; the shooter's finishing against the keeper decides goal/save/post/off, normalised per style so goals average expGoals. In-match fatigue uses `liveEnergy` (press/tempo burn energy; `minuteFatigue` deducts rating below 82 energy; tired players get injured more; subs come on fresh). AI clubs get roles from attributes and a mentality from the strength gap (`aiPrepare`) and switch by score from 45'. `scripts/sim-balance.js [rounds]` prints goals/match, result split and upset rate by gap; `tests/engine.test.js` guards all of it (stronger side by 7+ points wins ≥55%, loses ≤22%).
- Sound (`17-cloud-sim-sound.js`): `AUD`/`audBus()` is a WebAudio mixer with crowd / sfx / music gains (`G.vol`, sliders in the settings card, `G.sound=false` mutes all). Recorded cues live in `assets/audio/*.opus` with an AAC twin (`*.m4a`, tried when Opus fails to decode, i.e. Safari) (`AUDIO_FILES`, credits in `assets/audio/credits.json`), lazy-decoded after the first tap (`audPreload` in boot). `CROWD` drives the match: `kickoff(att)` plays the bed as overlapping 24 s segments with a 3 s crossfade (never a loop point, which iOS cut audibly) at a volume from attendance, `chance`/`goal` duck the bed and recover, `song` from 80' when leading, `halftime`/`pause`/`resume`, `end()` fades everything (no cue is ever cut; `render()` of any other screen fades the stadium out). The synthesized `SFX` tones remain the fallback when a file is missing.
- Multiplayer v1 (`src/js/35b-multiplayer.js`, schema `supabase/migrations/20261023120000_multiplayer.sql`): two human managers in one league, host-authoritative. The host's phone simulates: every week each manager runs his club and presses "מוכן" (`mpReady` → `mp_ready` with the whitelisted commands of `mpCommandsFor`: formation, lineup, captain, mentality, tactics, plan, roles, ticket); when both are ready, or the turn timer (`turn_min`) has expired and the host is ready, `mpHostSimulate` applies the guest's commands (`mpApplyCommands`), plays the whole week instantly (`MP.capture` marks both human clubs so `isHumanClub` gives them fixed lineups, their own roles/mentality and chemistry; `runInstant` pushes their matches to `MP.captured`), records those matches (`mpRecord`: events, score, stats, man of the match) in `G.mp.lastWeek` and commits gzip+base64 state with `mp_commit` (optimistic revision). Guests load each new revision (`mpLoadRevision`, keeps `G.me`/`G.mp`) and both phones watch their own recorded matches through the live screen in playback mode (`mpPlayback` → `M.playback`; `stepMinute` only replays events via `mpPlaybackStep`; no subs, no settle, `MP.watching` blocks `render()`). Guest + invite code / `?join=CODE` link, anonymous auth, Realtime on `mp_leagues`/`mp_members` plus a 25 s poll, presence via `last_seen`. No onboarding ceremony and no transfer market in multiplayer (`mpNoMarketHTML`). Config: `__SUPABASE__` is filled by the build from `SUPABASE_URL` / `SUPABASE_PUBLISHABLE_KEY` (environment, `.env`, or the Pages workflow secrets), `localStorage.goalasso_supabase` overrides at runtime, `window.__mpClientFactory` injects a client (tests). `tests/multiplayer.test.js` runs host + guest jsdom windows on an in-memory fake of the SQL functions. `.env.example` lists the only public values the client may use.

- Live play (`37-live.js`, `36e-shouts.js`, `36f-penalty.js`, `15-live-play.css`; `tests/engage.test.js`):
  - Speed buttons `תקציר` / ×1 / ×2 / ×4, remembered in `G.spx`. Highlights (`תקציר`, `hl`) runs quiet minutes at 230 ms and holds the clock on a minute with a key event (`hlHold`), so a match takes about 40 s. ×1 is `G.speed` seconds (90 by default).
  - Touchline shouts: `M.voice` fills by 100/12 per match minute; a shout (`shoutStart(M,club,k)`, `k` = press | all | calm | hold) lasts `SHOUT_MIN` minutes. The effect is in `07-engine.js`: `shoutAdj` adds expected goals per 90 to both sides and to possession, `shoutTick` burns or restores energy through `M.burn` (read by `liveEnergy`), calm halves cards and cancels the opponent's momentum. Only the live screen starts a shout: simulated matches, AI clubs and multiplayer playback are untouched, so the balance tests are unaffected.
  - Penalties the manager takes himself: `stepMinute(M,ui)`; when `ui.pen()` is true and the user's club is involved, `penAward` parks the penalty in `M.pendingPen` and the live screen reports the outcome with `penResolve(M,club,taker,'goal'|'miss',how)`. A parked penalty nobody answered is decided by the next `stepMinute`. The picture is one close-up from behind the taker (his back, the ball, the keeper's face). For our club the user kicks (press, steer the swaying sight, release); against it he keeps goal with eight quiet arrows on the goal (`.pg-dirs`, placed at `PEN_ARROW`; the last one tapped before the strike counts, none = the middle). The computer's taker draws one of the same eight areas (`penAiShot8`: corners more often and less scatter for a better finisher) and `penKeep8` decides: wrong side = goal, right side saves most at the chosen height, fewer one height away; keeper and finisher quality shift it. Rules are pure functions (`penFrame`, `penSaveP`, `penKickOutcome`, `penZone`, `penKeep8`, `penShootoutDone`). The beginner match clock runs the same overlay (`BpenTake`: `Btick` passes `BpenUI` to `stepMinute` and waits while `BpenBusy`). A level knockout tie (`cup`, a final, a second leg level on aggregate, `ctx.ko`) opens `penShootout`, which sets `M.pens` and `M.penScore`. `G.penGame===false` (settings) keeps everything automatic; the legacy live suites set it. The picture is `assets/demo3d/penalty.js` (the stadium of the 3D highlights, one view reused for a whole shoot-out) with an SVG fallback `penStage2d` (no WebGL, reduced motion, jsdom); both implement `toScreen/fromScreen/shoot` (the taker's run-up is part of `shoot`). Both teams wear the colours of the match (`penKits` → `matchColors`, so a clash moves the away side to its second kit) and the keeper a colour neither side does. The 3D view is only for a browser with a graphics chip (`pen3dOK` asks for WebGL with `failIfMajorPerformanceCaveat`; `G.pen3d===true` takes it anyway, which the live check uses on its software-rendered runner, `G.pen3d===false` never does); a view that draws under ten frames a second reports `onSlow` and later kicks of the session use the flat picture (`pen3dBad`). The kick's ten seconds run on `penClock`, which counts shown frames only (a slow frame or a tab in the background adds 0.1 s at most).
  - Haptics: `buzz(kind)`, off with `G.haptic===false`.
  - The live picture (`tests/live-picture.test.js`): a score between two teams that stand side by side is `scoreSides(gh,ga)` (`02-util.js`, `.sides`): home number first, so beside the home side on the right; never one left-to-right text "1 : 0" (prose such as "ב"ש 1:0 מכבי" keeps the usual notation). In open play the ball has an owner on both 2D pitches (`carryMinute`/`carryFrame` in `14-arena-svg.js`, shared with `15-arena-pixi.js`): it is played to one outfield player of the side in possession, stays at his feet until the next pass (at least `CARRY_MIN` ms, so the name is readable at ×4) and his name is shown (`st.car`, `st.carNow`, SVG `st.carLab`); shots, corners, celebrations and replays have no carrier. The picture takes the same two `Math.random` numbers per minute as before, the rest comes from its own generator (`st.rs`). SVG name labels keep one size on screen (`LAB_FS`). In the 3D highlights `eventFrame` returns `holder` (the passer of the final ball when `clip.assist` is known, then the shooter, the keeper after a save) and `live.js` places `.m3-tag` above him. The score at the end of a shoot-out and under the penalty title is `scoreSides` too. The foreign-player limit also holds for substitutions (`subBreaksForeign` in `doSub`/`autoSub`; `foreignLimited` = clubs of the Israeli leagues, not the quick tournament): a foreigner may come on beyond `MAX_FOREIGN_XI` only for a foreigner. The beginner result dialog shows, under the score, who scored and assisted and who was carded (`BmatchFactsHTML`) and the ratings of both sides (`BratingsHTML`, from `matchRatings`). The beginner mode lists real free agents only (generated ones are dropped on create and on load; the "invented" label follows `inventedPlayer`).
- Between matches (`36c-engage.js`, `36d-career.js`, `16-engage.css`):
  - Career book `G.car` (save v13, `carBackfill` for older careers): counters `n`, streaks `st`, records `rec`, trophies `tr`, achievements `ach`, `fresh` (unlocked, not shown). Fed by `carAfterMatch` (from `settle`, never friendlies), `carTrophy` (from `recordMoment` and the season end), `carSeasonEnd`, `carSigning`, `carWeekly`. Achievements are rows in `achDefs()` (`[id, name, text, category, target, value, stars]`); stars give the manager level (`carLevel`). Screen: `viewCareer` (`G.view='career'`), home card `careerCardHTML`.
  - `nextHooks()` lists facts about the coming week (derby, top of the table, streak, a player one goal from a round number, an achievement almost done); shown on the home card and in `nextUpModal` after a live match.
  - The envelope: `surpriseRoll(M)` runs once after each competitive match (`afterMyMatch`); about one match in three, never twice in a row, never more than four without. It applies a small real effect at once (academy jump, a free scout report on a real affordable player, sponsor bonus, fans, form, recovery, morale, board) and records it in `G.env` and the news; `envelopeOpen` only reveals it (after a live match through `postMatchFlow`, otherwise through `maybeShowQueued`).
- Quick tournament (`36g-blitz.js`): draft one of three real players for each position (`blitzPool`, rated like `rawSquad`), links between team-mates of the same club or country give up to +3 (`G.mentalBoost`), then four knockout rounds against real clubs at rising strength (`BLITZ_ROUNDS`), played on the normal live screen (`ctx.ko`, highlights by default). It runs on a throw-away state: `blitzSandbox` swaps `G` for a `newGame()` state flagged `G.blitz`, the career waits in `BLITZ.career`, and `SANDBOX` makes `save`, `saveSync` (through `save`) and `emergencyFlush` no-ops; `blitzExit` restores `G` and `uid`. Only the record (`BLITZ_KEY`) and the current run (`BLITZ_RUN`) are kept, in localStorage. Never call `settle`, `afterMyMatch` or `finishWeek` in the sandbox.
- אלוף הפנדלים (`36j-penalty-cup.js`, `17-penalty-cup.css`; `tests/penalty-cup.test.js`): penalties only, from a button outside every career (`pcupEntryHTML()` on the start and home screens of both pages; any `[data-pcup-open]` opens it). Lobby `#pcup` (z-index 44, under the penalty overlay): pick a club (`pcupTeams`: the Israeli top division + the 24 strongest real European squads), then `cpu` (an opponent chosen or drawn, then the shoot-out of the full game, `penShootout`), `seat` (two people on one phone at the same moment, facing each other, `pcupAskBoth`: each has a light strip over his own edge of the picture, the first club's at the bottom, the second's at the top and turned to its player; one kicks and one keeps goal and the roles swap with every kick; the picture takes the whole screen (`root.pc-face`: no title, no bottom bar; the 2D stage extends stand and grass instead of cutting the posts off on a very tall stage); the pitch, not the phone, turns to the kicker: when the far player kicks, `#pgStage.pc-flip` turns `#pgView` by half a circle, so the taker's back is always at the kicker's edge and the goal at the keeper's, and a slide is read in the picture as it lies; nothing runs until one press on the button in the middle, which starts a `PCUP_COUNT` count of three seconds; each slides a finger across his strip, before or during the count, and `pcupSwipeDir` maps the travel on the screen to one of the eight directions, so there are no buttons; pointer events, so two fingers are both heard; the strip shows only that a choice was made and the last slide counts; at the whistle a small arrow at each edge shows what was chosen (`.pc-chose`); no slide = the ball goes anywhere, the keeper stays) or `net` (two phones, a room code or a `?pen=CODE` link). A duel kick is `pcupResolve(kick dir, dive dir, finisher, keeper, rnd)`: pure, driven by a seeded generator, so both phones get the same result. Online runs on a Supabase Realtime broadcast channel `pcup:<CODE>` (`pcupChannel`; `window.__pcupNet` injects a transport for tests): `hi{team}` → `start{a,b,first}` (the host's takers as squad indices and skills, used by both phones), then per kick commit `c{k,h}` and reveal `r{k,d,n}` (a reveal is sent only after the other commit arrived; a reveal that does not match its commit stops the match); every message carries the sender id, a third phone gets `full`, unanswered messages are repeated every 1.2 s and 30 s of silence ends the match. No database tables are involved. It runs on a throw-away state like the quick tournament (`G.pcup`, `SANDBOX`, `pcupClose` restores `G` and `uid` and re-renders); only the record (`PCUP_KEY`) is stored. A web page cannot use Bluetooth or find phones on the local network, so "same room" is the one-phone mode. The beginner live screen also has the highlights speed (`data-bspeed="hl"`, `hlHoldMs`) and the shout bar (`shoutMount(M,{save:Bwrite})`; never Pro's `save()` there).
- Beginner career (`src/beginner/app.js`, `tests/beginner-career.test.js`): the title screen of the beginner page (`renderSplash` with `window.BEGINNER`) asks a new coach for his name (`BsplashGo`), has no network button and carries a small link to the full game; then the league choice is its own screen in front of the stadium photo (`.bpick-page`, drawn flags `Bflag`, then the Champions League, network play and אלוף הפנדלים last: the `.bpick-page` render returns `BstartHTML()` alone, so the penalty card of the start screen is not on it and its entry belongs in `.bmodes`), then the club and the contract. Network play is the last card of the start and home screens. Beginner tips (`.blearn`) are hidden after two rounds (`Btips`, `body.btips-off`, a footer link brings them back). The market's second tab lists any league of the catalogue (`#bmleague`, `Bmleague`; a league's clubs are built the first time it is looked at). In detail, the opening is three steps (`Bstart`, `BstartHTML`): the coach's name, a league (`Bcat()`: Israel's top division, Leumit, Liga Alef north and south, and the foreign leagues with real squads, built from `WORLD_LEAGUES` + `EURO_CLUBS`), a club, then the contract dialog; `Bcreate(key,{name,league})`. Every club carries a stable key `c.bkey` (`mta`, `eu<n>`, `l:<id>`, `a:<name>`, `w:<league>:<name>`); only the clubs of a league somebody works in are built (`BensureLeague`), so the localStorage save stays small. Coach state in `G.beginner`: `coach`, `leagueId`, `contract {years, wage, goal, since}`, `board` 0..100 (`BboardAfter`: result against the strength gap, then place against the goal), `offer` (mid-season, same league only: he joins the table as it stands), `out {why, offers}` (dismissed by `BcareerRound` from round 8 when the board is at 12 or less, or resigned; `BoutHTML` is then the whole screen and there are always at least two offers), `verdict` at the season summary (`BseasonVerdict`: goal met → stays, contract renewed when it ran out, offers from other clubs; far below → released). `BtakeJob` moves him: same league in mid-season keeps season and table, anything else starts a new season at the new club. Careers saved before this get keys and, when their league is on the list, a contract (`BensureKeys` in `Bload`); a training league that is not on the list plays on without a board. The Champions League is a league to choose (`cl1`, catalogue entry `cl` with `cup:true`, last in `Bcat()` so `BcatFind` finds a club in its own country first): the `BCL_N` 16 strongest clubs of the foreign top divisions, at most four of one country, home and away; offers from outside it come from the countries' leagues only (`BjobPool`). Inside a career of a country's top division it is also a competition (`b.cl = {season, ids, alive, stage, at, ties, res, out, won, champion}`, drawn by `BclDraw` at the end of `Bseason`): the coach's club plays it when it qualified (`BclQualified`: the first `BclPlaces(l)` of last season's table kept in `b.clq`, in a first season or a new league the strongest clubs of the league), with the strongest clubs of the other countries (four of one country at most) to sixteen; four evenings of one match each (`b.cl.at`, league rounds before which they are played), a level match goes to penalties (the overlay `penShootout`, `penAutoShootout` when skipped or `G.penGame===false`). `BclTie()` is the coach's tie once its evening has come: `Bhome`, `Bprematch` and `Bplay` take it before the league round (`M.bCL` = stage, `ctx.ko`), `Btick` hands the finished match to `BclFinish` (gate, prize `BCL_PRIZE`, board, `b.honours`), `BclClose` plays the other ties and draws the next stage, `BclNight` plays the evenings the coach has no part in. Screens: `BclCard` on the home page, `BclLeagueHTML` under the league table, a line in the season summary for a club that qualified. Careers saved earlier get it from their next season. - Version (`36i-version.js`): the build writes `<meta name="goalasso-build">` (content hash), `<meta name="goalasso-built">` (time of the commit, Israel time) and `version.json` (git-ignored; the Pages workflow publishes it beside the pages). `buildStampHTML()` shows the build in the beginner footer and in the settings card of the full game. `updateWatch()` (both boots) asks for `version.json` when the page loads or returns to the front (at most every two minutes) and offers a newer build in `#updBar`: the career is saved, then the page is replaced with `?v=<build>` so no cache answers. A home-screen app that is only resumed never reloads by itself; this is how it gets new builds.
- Notifications (`36h-notify.js`, `assets/sw.js`): opt-in per device (`localStorage.goalasso_notify`), only while the game is open in the background, only for real events of network play (`mpNotifyReady`, `roomNotify`). The service worker shows the notification and focuses the game; it caches nothing. There is no push server.

## Rules
- Keep saves backward compatible: `SAVE_VERSION` + `MIGRATIONS` in `src/js/22-save.js`. Careers persist in IndexedDB (gzip, one record per slot + `backup:N`, career id + revision with compare-and-set); browsers without IndexedDB and the jsdom suites use the legacy localStorage layout. `save()`/`load()`/`installCareer()` return a Promise in IndexedDB mode and a boolean otherwise — wrap with `Promise.resolve(...)` when the outcome matters.
- UI text in natural Hebrew; isolate numbers/Latin with `<bdi>`.
- Never put a Supabase service_role/secret key in the repo or the client.
- Multiplayer: keep it host-authoritative and gated on `G.mp`; guests never write league state, only their member row. No voice/WebRTC yet (planned: STUN only).
- Tests use `window.__ilmNoSplash=1` (skip intro) and `window.__ilmUnlock=1` (all clubs selectable).
