# GOALASSO · מאמן כדורגל

Hebrew (RTL), mobile-first football management game. Single-file web build.

## Layout
- `src/index.html` — document shell (doctype, meta, manifest/icons, markup) with `__CSS__` / `__JS__` placeholders.
- `src/styles/NN-*.css` — stylesheets, concatenated in file-name order. Later files override earlier ones: `07-theme-direction-a.css` is the current theme, `08-cinematic-lineup.css` the lineup screen (the stadium photo `assets/lineup-arena.*` with round portraits and a name plate — rating, name, fitness as the ring colour — placed by `pitchProject`/`ARENA` in `36-views.js`; `12-formation-board.css` keeps the beginner mode's formation board on `assets/lineup-reference-stadium.jpg`), `09-phone-readability.css` the mobile overrides, `10-market.css` the transfer-market search/filters.
- `src/js/NN-*.js` — the game, one shared script scope (no ES modules). Load order = numeric prefix: `01-data` → `02-util` → `03-players` → … → `36-views` → `36b-broadcast` … `36h-notify` → `37-live` → `38-boot`. Function declarations are hoisted, so views may call engine code; `const`/`let` must be declared in an earlier file than their first top-level use. Put new code in the file that owns the subject (engine in `07-engine.js`, money in `18-week-flow.js`, screens in `36-views.js`, persistence in `22-save.js`).
- `src/build.py` — `python3 -I src/build.py` → writes `ligat-haal-manager.html` at the repo root (concatenates the modules, embeds data, splash, logo and the portrait manifest). Placeholders `__CLUBS_JSON__`, `__EURO_JSON__`, `__DATA_META__`, `__SPLASH_IMG__`, `__LOGO_IMG__`, `__PLAYER_VISUALS__` are filled by the build.
- `data/*.json` — Israeli club squads; `data/euro/*.json` — European squads.
- `assets/` — media loaded at runtime by relative path (intro/signing videos, lineup stadium, newspaper photos, trophy moments). They must sit next to the built HTML.
- `tests/*.test.js` — jsdom suites (`npm install`, `npm run build`, `npm test`). A suite passes when its last line shows `errors []` / `errs []`. `idb-save.test.js` runs the IndexedDB path on `fake-indexeddb`; `window.ILM.ready` resolves after boot and `window.ILM.whenSaved()` after the pending write.
- Player portraits: `scripts/build-portraits.py` turns the verified source photos (`data/visuals/source-photos/`) into canonical 240×300 transparent WebP cut-outs in `assets/facepacks/` (schema 2) and records each result in `data/visuals/portrait-audit.json`; manual decisions live in `data/visuals/portrait-overrides.json`; `scripts/portrait-report.py` writes `docs/portrait-audit.md`. The game never crops faces at runtime (`portraitGroup` / `cinematicPlayerHTML` in `36-views.js`); anything not `ok` renders the designed club-kit monogram fallback. Never assign a face to a different player, and never match European players to Israeli faces by name.
- European portraits (real squads in `data/euro/`): `.github/workflows/fetch-portraits.yml` (manual; runs `scripts/fetch-commons-portraits.py`, identifies each player on Wikidata by exact name + club / birth year and downloads freely licensed Commons candidates with author/licence) → branch `portrait-sources`. Locally, `scripts/import-commons-portraits.py --sources <portrait-sources checkout> --clubs …` picks the first candidate the pipeline accepts in strict mode (a player keeps the face he has and recorded refusals are not measured again unless `--fresh`; decisions are cached per file and pipeline content in `<sources>/.import-cache.json`) and writes `data/visuals/source-photos/eu-<club>.json` (git-ignored: the originals live on `portrait-sources`) + `data/visuals/euro-players.json` (identity, source, licence, credit, fallback reasons); then `build-portraits.py --only eu-<club>,…` and `--skin-only`. Files rejected on visual review go in `data/visuals/portrait-reject-files.json`. Files the strict checks refuse but a visual review accepts (frontal, single subject, verified identity) go in `data/visuals/portrait-accept-files.json`; a candidate with an attribution licence and no recorded author is never used. A second pass for players still without a face (`fetch-portraits.yml` input `more=true` → `--more`): only the players listed as unresolved, the whole Commons category (200 files), sub-categories and full-text search, players the first pass could not identify are asked again (`identify`, which also accepts the one footballer of that name whose English article lists this club in its infobox, `infobox_clubs`), files already judged skipped, the new ones ranked by `portrait_score` (the file's own "depicts" statements, the name in the file name, portrait words against group/match words, shape) and the best eight downloaded as `…-m<k>.jpg` with `depicts` recorded; the import treats a file that depicts this player and nobody else like his Wikidata image. A file nobody names (an unnamed file of his category, a name-search hit) is used only when its single face is the face of one of his named pictures (`FaceMatch` in the import: OpenCV SFace, cosine ≥ `FM_MIN` 0.55 for a file of his own category, `FM_MIN_SEARCH` 0.60 for a name-search hit, never a file whose "depicts" names somebody else; a category file whose name names somebody else as well (`two_names`: another name right before his, or "A and B") needs the face match too; the model is not in the repo, `$SFACE` or `~/.u2net/sface.onnx`, without it nothing is matched); the evidence is written to the face's `reviewed` field and `--review DIR` saves reference and candidate side by side for the visual check. Squads named in Hebrew (Leumit) are identified by Hebrew label/alias/article title + the club on the item (`identify_hebrew`, no birth-year fallback). Faces resolve by club + English name only; credits ship in each pack and show on the player profile and under מידע → תמונות שחקנים.
- Real squads from Wikipedia (clubs in `data/config/world-clubs-wiki.json`): `.github/workflows/fetch-squads.yml` (manual; `scripts/fetch-wikidata-squads.py`: the article's current-squad templates, else the club's squad template with positions from Wikidata, Hebrew Wikipedia for the Leumit clubs; a player "on loan from" another club is a squad member) → branch `squad-sources` (`squads/<key>.json`, `_debug/` dumps for pages that did not parse). Locally `scripts/import-squads.py --sources <checkout>/squads --clubs …` writes `data/euro/<key>.json` (one factor per squad puts its best-14 rating on the club's strength + 1) and lists the players as unresolved in `euro-players.json`; `--merge` adds players a newer fetch lists (nobody is removed), `--sync-identities` afterwards, `--rescale` re-applies the value rule. Portrait candidates for new or changed squads are fetched from a work branch (`ref=squads-wip`) so nothing half-done deploys. Only one portrait import may run at a time (it rewrites `euro-players.json` as a whole).
- Real players only: the config groups are `world` (market clubs), `euro` (European opponents of `EURO_CLUBS`) and `leumit`; a club with no squad on Wikipedia is removed from the game rather than shown with invented players (Young Africans, Petrocub). `inventedPlayer(p)` (no English name, no Israeli identity) marks generator players: they are never listed on the market, in the search or as free agents, the free-agent list starts empty, and real squads are never padded. Invented players remain only where the game needs bodies and has no names: `topUpPlayer` asks the club's youth side first, then `registeredName` — a name from the club's own registered squad (`RAW_EURO[c.name]`, Israeli lists only, since a foreign name carries a nationality and a foreign-player slot with it) that nobody in the game is using — and invents one only when the club has neither. A club promoted from Liga Alef arrives with all its registered players, and nobody's contract runs out on the day it arrives (`cameUp` in `20-season-end.js`): it used to go through the same expiry as everyone else, drop under the minimum, and be handed an invented player — first a club with twenty-three names on file (fixed by `registeredName`), then one with exactly twenty, which has no spare name at all; `tests/alef-youth.test.js` caught each about one run in ten and blocked deploys. `tests/engage.test.js` had a flake of its own: an injury in the first minute left nine outfield players for a shout to burn. Hebrew spellings for second-tier players that the sources give in Latin letters live in `data/config/leumit-names-he.json` (transliterations; `import-squads.py --clubs all --names`). Save v12 (`migrateRealOnly`) applies all of this to existing careers.
- Liga Alef and youth (`scripts/import-ifa-rosters.py --xlsx <workbook>`, the federation's registered squads; the workbook is not kept in the repo): `data/euro/a_<key>.json` (35 clubs of both districts, `league: alef_north|alef_south`, city and approximate shirt colours; the build lists them in `RAW_ALEF` = `ALEF_POOL`, so the two clubs that come up each season are real clubs with their real squads) and `data/config/youth-squads.json` (senior club → names of its youth side, embedded as `RAW_YOUTH`). The source has names only: for Liga Alef the position and value are dealt by the import from the player's id (`generated` in each file), ages are drawn by the game; youth are stored as names only (no ids, links, dates or photos, and masked names are skipped). In `03-players.js`: `makePlayer` tags generator players `gen:1` (`generatedPlayer(p)` also recognises them in older saves), `giveRealName(p,club,taken)` gives a prospect a name of his club's youth side once per career (`G.yused`) and never while that name is already in the game, with `visualId:null` so no portrait is matched by name; `realizeYouth()` (new career, season end) and `topUpPlayer` (season-end top-ups: a graduate aged 18–20) use it. Federation photos are not used: they are not freely licensed and a third of them show minors. Save v14 (`migrateAlefYouth`): generated squads of promoted clubs become the registered ones and the other clubs' generated prospects get real names; the manager's own club is untouched. `tests/alef-youth.test.js` covers it.
- A senior squad from the federation's registered list (`scripts/merge-registered-squad.py --club l_<key> --pdf <sheet.pdf>` or `--list`): the Wikipedia squads of the second tier seldom know an age (a whole squad stood at 25) and lag behind the registrations; the federation's club page lists every registered player with month and year of birth and nationality. The script reads **the text only** of a sheet made from that page: each player the game has gets his real age (only the age is kept, not the date), the registered players it lacks are added with `en` = the Hebrew name (as every squad without Latin names), and nobody is removed. The list has no positions or values, so for the added players those are the game's (`registered.generated` in the file: positions dealt toward a normal squad shape, values under the squad's weakest). Names are matched exactly, without middle names, by a surname only one player carries, else `--alias "list name=game name"`; the report prints every match. Afterwards: `import-squads.py --clubs <key> --rescale` (ages move `euro_rating`, so the best-14 rule has to be re-applied; it now keeps the file's `merged`/`registered` notes), `--sync-identities` (`tests/euro-portraits.test.js` wants every player listed), `scripts/build-league-pool.py`, and the owner pastes `supabase/install-league-pool.sql` again or the shared league cannot sell the new players. **The photographs on such a sheet are the federation's registration pictures and are never used**, whatever file they arrive in. First used for הפועל כפר סבא (21 ages, 10 added, 34 players). There is **no fetch workflow for football.org.il and none is to be built**: the site sits behind Cloudflare and answers any plain request with 403 — the web reader, a GitHub runner that says honestly what it is, even `robots.txt` (probed 2026-11-16) — and a block is not something to get around with browser headers, a headless browser or a mirror. The lists arrive as a sheet or workbook the owner makes, or are read page by page in his own browser when it is linked to the session.
- 3D look (`assets/demo3d/world.js`, one world shared by the highlights and the penalty view): a floodlit evening, the same art direction as everything else in the game. `buildWorld` owns it — navy sky and fog, a dim hemisphere, a cold bank high over the near touchline that casts the shadows, a dimmer bank from the far corner, a warm bounce off the stands, and an additive halo sprite on each of the four pylons. Before this the scene was lit as a bright afternoon and only the penalty view darkened the sky behind it, so the pitch glowed like noon under a black sky (and under a photographed *night* stand). The instanced crowd is about 15,000 spectators at `STEP` .52 m apart over 18 rows, with a little jitter so the eye finds no column: density is the whole thing, because at .84 m apart a spectator is an object you can count and a grid of countable objects reads as a field of cones however well each one is shaped. A spectator is a **cut-out, not a solid**: eight poses drawn into one 512×80 atlas (standing, an arm up, both arms up, arms folded, leaning, a scarf overhead, a flag, hands on the rail), picked per instance from an `aCell` attribute that offsets `vMapUv` in the vertex shader, cut out with `alphaTest` so rows still occlude. Every solid shape the geometry could afford gave fifteen thousand people the same outline, which reads as a field of bottles whatever colour they are. The cut-outs are `MeshBasicMaterial`: a flat vertical plane facing the pitch takes almost nothing from a floodlight above it and renders black when lit, so the palette carries the night instead. **Never set `vertexColors` on them** — three.js defines `USE_COLOR` from that flag alone and the shader then multiplies by a `color` attribute the geometry does not have, which reads as zero and paints every spectator black; `setColorAt` works through `USE_INSTANCING_COLOR` on its own. The head stays a lit instanced icosahedron in skin tones, which is the speckle that breaks the colour up. `crowd.dress(a,b)` gives about a third of them the club's colour dimmed hard and the rest a dark night palette, and darkens by height, which is both true and the only depth a wall of instances gets. **The gate** is the block behind each goal, `ULTRA_W` 9 m either side of the centre, marked on each spectator as he is placed and everything else follows from the mark: its poses are the ones with the arms up, the scarf overhead and the flag, `aUltra` makes the vertex shader bounce it all match rather than only on a goal, and `dress` paints it one colour (a sixth stay in coats, or the block is a flat sheet). Over it fly 56 flags — a plane that waves in the vertex shader on a pole, two draw calls — and pyro: 34 additive quads that rise, spread and fade on `uTime` with the fade carried to the fragment shader as a varying, plus 14 hot cores. The stand owns its own weather; the scene only advances the clock. **No lettering and no badge anywhere in it**: a real club's tifo is that club's own work, so what the gate flies is its colours. A kit too dark to be seen at night is lifted toward a cool grey while it keeps its hue, or the gate paints itself in the stand's own colour and vanishes — the same bug the flat picture had. The three pitch spots are real geometry (`CircleGeometry`, r .11): painted into the 2048×1024 grass texture they were six pixels across, which the penalty camera magnified into a grey puddle under the ball.
- Lighting the surfaces (`buildWorld`): `scene.environment` is a 64×128 gradient — night sky, dark horizon, lit pitch — run through `PMREMGenerator`. A standard material lit only by lamps has one bright side and one black side and reads as plastic; an environment gives it light arriving from every direction, which is most of what separates "rendered" from "flat", far more than polygon count. The players' cloth is roughness .72 with `envMapIntensity` 1.15 so the forms carry a sheen. This is also the thing that would still be missing if a modelled character were dropped in: a bought mesh under flat lighting still looks flat.
- The players (`assets/demo3d/actors.js`): a skinned rig built from ellipsoids and tapered cylinders, so every proportion is a number. What makes one read as a person rather than a doll, in order of how much it buys: **proportion** (the head was 6.7 heads to the full height, a man is about 7.6, and the shoulder balls at ±.245 with r .105 put the body's widest point at 70 cm across, which is armour), **a neck** (longer and thinner than seems right — it is the strongest single cue), and **the pose** (a keeper standing to attention was most of why he read as a doll; he is now low, feet apart, knees bent, weight forward, hands away from his body, with a slow idle lean). Spheres are 14×10 and cylinders 14-sided, because the faceting of a 10×7 sphere shows the moment anyone looks closely. Note the game never renders a player larger than about 80 px: the penalty camera is 11 m from the keeper. Proportion and silhouette pay at that size; facial detail does not, and a true close-up would need a modelled mesh rather than primitives.
- First person: the 3D highlights have two extra cameras (`עיני הבועט`, `עיני השוער` in `assets/demo3d/live.js`: the camera sits at the player's eyes, his own body hidden). Coach's-eye video clips (press conference, tunnel, dressing room, trophy…) are described in `data/config/video-prompts.json` and generated by `.github/workflows/grok-video.yml` (manual; `scripts/grok-video.py`, xAI video API, repository secret `XAI_API_KEY`) onto the `video-sources` branch for review; no real people, badges or readable text in the prompts.
- Portrait review: `scripts/check-portraits.py [--sheets DIR]` measures every shipped cut-out (frame, eye line, face size, hair against the top edge, sides, opacity, sharpness). The import (`import-commons-portraits.py`) writes the accepted cut-out into the pack itself (cache in `<sources>/.import-built`), so `build-portraits.py --only …` is only needed for faces decided by an older cache. Round avatars (`.rt-face`, `.bc-face`) are framed by `faceFrameStyle(p)`: the window starts 12 px above the player's own hair line (`PLAYER_VISUALS.faces[].top`, from the audit's `hairTop`), never lower than 20 px. A cut-out without shoulders (`bust:0`, about one shipped face in sixteen) is finished by drawing in `portraitGroup`: the photograph is masked under the jaw line to the jaw and a column of neck (soft edges), a neck in the player's measured skin tone lies behind it, and his club's shirt is drawn **in front** — shoulders at a believable width, a neckline the real neck shows through. The shirt used to be a flat dome behind the photograph, so whatever the cut-out still held under the chin (a jacket's collar, a hood, a scarf) lay on top of it and the head read as pasted on. The geometry is fixed because the canonical cut-out puts the eyes at 36% and the mouth at 48.5% of 300, so every chin is near y 170.
- Broadcast package (`36b-broadcast.js`, `14-broadcast.css`; presentation only, reads `M` and its events): `#bcLayer` inside the arena (a flat strip when match graphics are off). `bcEvent` queues one plate per key event (goal, card, substitution, injury, big save) with the player's face; `bcScore` pulses the score bug and marks sent-off players; `bcSlate(M,h,a,'half'|'full')` is the statistics board at the breaks (score, scorers, possession, shots, xG, man of the match). The app header (`#top`) is hidden while the live screen is up; `render()` brings it back. `tests/broadcast.test.js` covers it.
- World transfer market (`11-market.js`, `viewWorld`; Israel tab `viewMarket` in `36-views.js`): clubs with data in `data/euro` show their full squad (`fillRealWorldSquad`, idempotent: a player is recognised by English name + origin club `p.from`, so re-valued data never duplicates him; `WORLD_SQUAD_V` marks the data generation, and a squad from an older generation that sits 3+ points under the club's strength is lifted back to it; run by save migrations v9 and v11); real squads are never padded with invented players; the 11 most valuable players are listed as in the squad but not for sale (`p.nfs`): talks open only with an exceptional offer (asking price ×2.4 at tier-1 clubs, ×1.9 elsewhere, no haggling below it, 2 rounds of patience). Every market club has a real squad (the generated 7-player list is only the fallback path for a club whose data is missing). "ליגיונרים ישראלים" = real players whose data nationality is Israel at clubs outside Israel. Name search gives live suggestions from 2 letters (Hebrew/English, accents and Hebrew final letters ignored) across Israel and all world leagues. `tests/world-market.test.js` covers it; `.github/workflows/live-check.yml` (manual) runs `scripts/live-market-check.js` on the deployed site at iPhone size and pushes screenshots + report.json to the `live-check` branch; the report's `play` section covers live play on the deployed build (shout bar, one penalty we kick and one we keep goal for, both through the overlay, with the view that drew them, career card, a quick-tournament draft and the return to the career); the script owns every penalty of its match, so a penalty the engine awards by itself is decided automatically there, and it reports `gpu3d` (would the game pick the 3D view on that browser by itself) and `slow3d` (the frame-rate verdict after the first kick). The `beginner` section opens `beginner.html` beside the page: score numbers on their own team's side, the carrier's name on the pitch, ratings of both sides in the result dialog. The `pcup` section is the beginner page's penalties: practice inside a career (`train`: his own club, straight into the shoot-out), then the entry page's משחק רשת → פנדלים (`entry`, `entry.png`) and two kicks between two browser contexts in one room over the real Realtime channel (`online.same`: both saw the same kicks). Each build carries `<meta name="goalasso-build">` (content hash) so the check can tell which build is live.
- Match engine (`07-engine.js`): three units per side from the XI (`unitStrength`: gk/def/mid/att by slot, roles blur them; captain, boosts, chemistry, mental programme and the training plan's `trainBonus` apply to all units). `expGoals` = attack vs the opposing defence on a convex curve (~0.08 goals per rating point, capped), scaled by midfield edge, plus home advantage, mentality, `tacticAdj`, and an 8-minute momentum after goals. Above `XG_SOFT` (3.2) expected goals for the two sides together only `XG_KEEP` (a fifth) of the surplus is kept, in proportion for both (tier-1 tactics, roles and forwards rated far above the keepers they face stacked up to 4.5 goals a match between Europe's richest clubs; now about 3.6, the Israeli league unchanged at 2.7); a touchline shout is left whole. Each minute a side may create a chance (rate ∝ expected goals); `chanceSpot` by style gives a location and real xG; the shooter's finishing against the keeper decides goal/save/post/off, normalised per style so goals average expGoals. In-match fatigue uses `liveEnergy` (press/tempo burn energy; `minuteFatigue` deducts rating below 82 energy; tired players get injured more; subs come on fresh). AI clubs get roles from attributes and a mentality from the strength gap (`aiPrepare`) and switch by score from 45'. `scripts/sim-balance.js [rounds]` prints goals/match, result split and upset rate by gap; `tests/engine.test.js` guards all of it (stronger side by 7+ points wins ≥55%, loses ≤22%).
- Sound (`17-cloud-sim-sound.js`): `AUD`/`audBus()` is a WebAudio mixer with crowd / sfx / music gains (`G.vol`, sliders in the settings card, `G.sound=false` mutes all). Recorded cues live in `assets/audio/*.opus` with an AAC twin (`*.m4a`, tried when Opus fails to decode, i.e. Safari) (`AUDIO_FILES`, credits in `assets/audio/credits.json`), lazy-decoded after the first tap (`audPreload` in boot). `CROWD` drives the match: `kickoff(att)` plays the bed as overlapping 24 s segments with a 3 s crossfade (never a loop point, which iOS cut audibly) at a volume from attendance, `chance`/`goal` duck the bed and recover, `song` from 80' when leading, `halftime`/`pause`/`resume`, `end()` fades everything (no cue is ever cut; `render()` of any other screen fades the stadium out). The synthesized `SFX` tones remain the fallback when a file is missing.
- Multiplayer v1 (`src/js/35b-multiplayer.js`, schema `supabase/migrations/20261023120000_multiplayer.sql`): two human managers in one league, host-authoritative. The host's phone simulates: every week each manager runs his club and presses "מוכן" (`mpReady` → `mp_ready` with the whitelisted commands of `mpCommandsFor`: formation, lineup, captain, mentality, tactics, plan, roles, ticket); when both are ready, or the turn timer (`turn_min`) has expired and the host is ready, `mpHostSimulate` applies the guest's commands (`mpApplyCommands`), plays the whole week instantly (`MP.capture` marks both human clubs so `isHumanClub` gives them fixed lineups, their own roles/mentality and chemistry; `runInstant` pushes their matches to `MP.captured`), records those matches (`mpRecord`: events, score, stats, man of the match) in `G.mp.lastWeek` and commits gzip+base64 state with `mp_commit` (optimistic revision). Guests load each new revision (`mpLoadRevision`, keeps `G.me`/`G.mp`) and both phones watch their own recorded matches through the live screen in playback mode (`mpPlayback` → `M.playback`; `stepMinute` only replays events via `mpPlaybackStep`; no subs, no settle, `MP.watching` blocks `render()`). Guest + invite code / `?join=CODE` link, anonymous auth, Realtime on `mp_leagues`/`mp_members` plus a 25 s poll, presence via `last_seen`. No onboarding ceremony and no transfer market in multiplayer (`mpNoMarketHTML`). Config: `__SUPABASE__` is filled by the build from `SUPABASE_URL` / `SUPABASE_PUBLISHABLE_KEY` (environment, `.env`, or the Pages workflow secrets), `localStorage.goalasso_supabase` overrides at runtime, `window.__mpClientFactory` injects a client (tests). `tests/multiplayer.test.js` runs host + guest jsdom windows on an in-memory fake of the SQL functions. `.env.example` lists the only public values the client may use.

- Live play (`37-live.js`, `36e-shouts.js`, `36f-penalty.js`, `15-live-play.css`; `tests/engage.test.js`):
  - Speed buttons `תקציר` / ×1 / ×2 / ×4, remembered in `G.spx`. Highlights (`תקציר`, `hl`) runs quiet minutes at 230 ms and holds the clock on a minute with a key event (`hlHold`), so a match takes about 40 s. ×1 is `G.speed` seconds (90 by default).
  - Touchline shouts: `M.voice` fills by 100/12 per match minute; a shout (`shoutStart(M,club,k)`, `k` = press | all | calm | hold) lasts `SHOUT_MIN` minutes. The effect is in `07-engine.js`: `shoutAdj` adds expected goals per 90 to both sides and to possession, `shoutTick` burns or restores energy through `M.burn` (read by `liveEnergy`), calm halves cards and cancels the opponent's momentum. Only the live screen starts a shout: simulated matches, AI clubs and multiplayer playback are untouched, so the balance tests are unaffected.
  - Penalties the manager takes himself: `stepMinute(M,ui)`; when `ui.pen()` is true and the user's club is involved, `penAward` parks the penalty in `M.pendingPen` and the live screen reports the outcome with `penResolve(M,club,taker,'goal'|'miss',how)`. A parked penalty nobody answered is decided by the next `stepMinute`. The picture is one close-up from behind the taker (his back, the ball, the keeper's face). For our club the user kicks (press, steer the swaying sight, release); against it he pulls with a finger toward the corner the keeper should go to (`penAimPad` / `penAimDir` in `36f-penalty.js`: a `.pg-pull` surface over the picture, a dotted line from the finger and a sight that rides the goal at `PEN_ARROW`; the last pull before the strike counts, none = the middle). The eight areas are still the unit of choice, because the duel commits a direction over the network, so the pull changes how a choice is made and not what is chosen; the old arrow pad (`.pg-dirs`) stays in the page but out of sight, for the keyboard, for assistive technology and for the live check, which clicks it. `pcupAsk` uses the same pull for both turns of a duel. Shirt numbers come from `ensureNumbers` (`37-live.js`), which `pcupSide` and `penShootout` now call themselves — a duel never plays a match, so without it every taker wore 9. The computer's taker draws one of the same eight areas (`penAiShot8`: corners more often and less scatter for a better finisher) and `penKeep8` decides: wrong side = goal, right side saves most at the chosen height, fewer one height away; keeper and finisher quality shift it. Rules are pure functions (`penFrame`, `penSaveP`, `penKickOutcome`, `penZone`, `penKeep8`, `penShootoutDone`). - Out of work (`BoutHTML`, `src/beginner/app.js`): dismissal or resignation shows three clubs that want him, and **ליגה אחרת** opens the whole catalogue so he can pick where to go next. `Bresume()` scores the career in strength points (a trophy 4, a job he was not thrown out of 2, a season 1, a dismissal −3, and how the board felt when he left), `BjobBand(why)` turns it into the band of club strengths that will have him, and `BleagueOffers(league,why,n)` draws three of that league's strongest clubs inside the ceiling. Inside a league he chose himself there is no floor, only a ceiling: a club below his level will always have him. The ceiling never falls below his own level (minus a notch when dismissed), because a coach of Liga Alef would otherwise have a band under every club in the game and nobody would answer. A league where nothing is within reach is listed greyed and disabled (`BleagueReach`, "מעליך") rather than answering with an empty screen, which is the résumé made visible and opens by itself as the career grows; cups are not employers and are left off the list. The offers he arrived with are kept in `b.out.first` and come back when a chosen league answers with nothing. The out-of-work list is `data-boutleague`, not `data-bleague`: that one belongs to the opening flow and `BstartClick` swallows it before this handler is reached. `tests/beginner-career.test.js` covers it.
- Version (`36i-version.js`): the build writes `<meta name="goalasso-build">` (content hash), `<meta name="goalasso-built">` (time of the commit, Israel time) and `version.json` (git-ignored; the Pages workflow publishes it beside the pages). `buildStampHTML()` shows the build in the beginner footer and in the settings card of the full game. `updateWatch()` (both boots) asks for `version.json` when the page loads or returns to the front (at most every two minutes) and offers a newer build in `#updBar`: the career is saved, then the page is replaced with `?v=<build>` so no cache answers. A home-screen app that is only resumed never reloads by itself; this is how it gets new builds.
- Notifications (`36h-notify.js`, `assets/sw.js`): opt-in per device (`localStorage.goalasso_notify`), only while the game is open in the background, only for real events of network play (`mpNotifyReady`, `roomNotify`). The service worker shows the notification and focuses the game; it caches nothing. There is no push server.

- Club crests (`assets/crests/c01..c61.webp`, 512 px, transparent, plus `crests.json`): a library of **invented** crests for the shared league — thirty subjects (animals, a crown, an anchor, a tower, a bridge, a compass…) in two shield shapes and palettes each, with no lettering and no reference to any real club, whose badges are trademarks and are never used. They were generated locally with Draw Things (FLUX.2 klein) from `goalasso-crests.js` and cut out of the flat white background by the edge-reachable white only, so a white eye or stripe inside the shield is kept. Regenerating: the app stores every image as a full-size JPEG in its own project sqlite, so a batch is collected from there rather than exported one by one.

- Design system (`src/styles/01-base.css` `:root`, applied by `19-system.css`, which loads last): one ladder for radius (`--r1..--r4`, `--rp`), elevation (`--e1` resting, `--e2` raised, `--e3` floating, `--e-press`, `--glow`), motion (`--t-fast/--t/--t-slow`, `--ease`, `--ease-out`), spacing (`--s1..--s6`) and a focus ring (`--ring`). Before it the seventeen stylesheets carried twenty-four different corner radii and seventy-nine different shadows between them, which is what made the game read as assembled rather than designed. `19-system.css` changes depth, corners, motion and interaction states only — never a size, a spacing or a layout — so nothing moves on any screen; it also gives every control a pressed state and the game its first visible `:focus-visible` ring. Anything new uses the tokens.
- Signing reveal (`24-reveal-moments.js`, `04-reveal-moments.css`): the press stage (`signing.mp4`) runs the first four beats; the last one, `rv-final`, leaves it for the dressing room (`assets/room-dressing.webp`, `REVEAL_ASSETS.room`). The photograph is landscape, so it is shown whole as a lit band across the top (`.rv-roomshot`, 5/4, masked at the bottom) over a blurred copy of itself (`.rv-roomblur`) rather than cropped to the phone, and the player's own peg is drawn on the far wall: a nameplate with his surname and number (`.rv-plate`), his club shirt on a hook (`.rv-hang`) and the manager who signed him (`.rv-coach`, `G.manager.name`). No lettering is baked into the photograph. `tests/txn.test.js` covers it.
- Moment art (`assets/moment-cup.webp`, `moment-champ.webp` portrait 832×1216; `room-dressing.webp`, `room-press.webp`, `prematch-crowd.webp` landscape): one art direction for all of it — floodlit night, deep navy and warm amber, shallow depth, fine grain — generated locally with Draw Things from `goalasso-moments.js`. Places, objects and light only: never a face, because the game shows real players' faces and a generated one beside them reads as fake, and never any lettering, which a diffusion model turns into nonsense. `.mo-card` fills with `cover` under a scrim (`::after`) so the words sit on darkness rather than on the trophy. Where each one is used: the dressing room closes a signing (above), the press room is the band across the top of the press-conference card (`.press-head` in `01-base.css`, from `pressHeadHTML` in `12-manager.js`), and the full stand at night sits behind the אלוף הפנדלים lobby (`.pcup`), darkened by a `::before` scrim so only its depth and its floodlights come through.

## Rules
- Keep saves backward compatible: `SAVE_VERSION` + `MIGRATIONS` in `src/js/22-save.js`. Careers persist in IndexedDB (gzip, one record per slot + `backup:N`, career id + revision with compare-and-set); browsers without IndexedDB and the jsdom suites use the legacy localStorage layout. `save()`/`load()`/`installCareer()` return a Promise in IndexedDB mode and a boolean otherwise — wrap with `Promise.resolve(...)` when the outcome matters.
- UI text in natural Hebrew; isolate numbers/Latin with `<bdi>`.
- Never put a Supabase service_role/secret key in the repo or the client.
- Multiplayer: keep it host-authoritative and gated on `G.mp`; guests never write league state, only their member row. No voice/WebRTC yet (planned: STUN only).
- Tests use `window.__ilmNoSplash=1` (skip intro) and `window.__ilmUnlock=1` (all clubs selectable).

- GitHub Pages: `.github/workflows/pages.yml` builds and deploys on push to `main` (enable Pages → Source: GitHub Actions). The custom domain goal-m.com (no www) has always opened on the beginner game: the shell's first script (`beginnerFirst` in `src/index.html`) sends its bare root to `beginner.html`; the full game is `index.html` there (the beginner title's small link), and a root with a query (`?join=`, `?pen=`, `?v=`) is left alone. `?pen` with no code is the direct link to the אלוף הפנדלים lobby (`pcupLinkOpen`), on either page.

- Shared league, server side (step 1 of `docs/shared-league.md`): `supabase/migrations/20261114210000_shared_league.sql` — `lg_leagues`, `lg_members` (team, crest, kit, money), `lg_squads` (one owner per player per league, which the primary key is), `lg_ledger`, `lg_fixtures`, `lg_results`, `lg_offers`, `lg_training`, `lg_pool`. Same shape as the room service: definer functions in `goalasso_private` behind thin invoker wrappers, `auth.uid()` checked in each, every table with RLS on and all privileges revoked from `anon`/`authenticated`. In a shared league the server owns the money, so **a price the client sends is not a price**: `lg_pool` is the one list, `lg_buy` reads it, `lg_sell` pays 70% of it, and an unseeded pool sells nothing rather than everything for free. The key is the club's Hebrew name + the player's English name — the one identity the built game can also compute, since `src/build.py` strips `qid`. `scripts/build-league-pool.py` → `supabase/seed-league-pool.sql` (8,171 players, for `psql -f`) and `supabase/install-league-pool.sql` (the same list packed for the SQL Editor). `tests/sql/league-base.sql` runs inside `tests/rooms-sql.test.js` on PGlite and also applies the seed, so an impossible age or a nameless player in `data/` is caught before anybody installs it. **The migration has to be applied to the project before the lobby works at all**: `supabase/install-league.sql` is the migration plus `notify pgrst, 'reload schema'` in one file for the SQL Editor (`tests/rooms-sql.test.js` checks the file matches its migration, so what is pasted is what was tested). Until it is in, every RPC comes back as PostgREST's English sentence about a missing function, which `35e-league.js` turns into one Hebrew line rather than showing raw.
- Shared league, the client (step 2 of `docs/shared-league.md`): the lobby and the club's identity. `35d-crest.js` is the **crest and kit generator**, pure SVG and pure functions — `crestSVG(spec,opts)` draws a 100×120 badge from `{shape,div,c1,c2,ink,emblem,tier}` (4 shapes, 7 divisions, 12 palettes, 10 emblems drawn for this game) and `clubKitSVG(kit,opts)` the shirt over the game's own `kitInner` outline. The same spec always draws the same crest, so a crest is a few fields on `lg_members.crest` and never a file. The club's name is SVG text squeezed into the band with `textLength`/`lengthAdjust` (a long Hebrew name shrinks instead of being clipped), never baked into an image; the year sits at the top, out of its way. A disc takes the same flat band as every other shape — a ring of Hebrew along a `textPath` renders mirrored in some engines. Every emblem has to read at 32 px, which is what a crest is seen at: a wing drawn from primitives reads as a shark fin however the feathers are cut, so the generator carries a bolt instead; a tower needs a flat-bottomed arched door (a rounded rect over a circle reads as a face); a flame needs asymmetry and a lick or it is a water drop; a lion needs a fur mane and ears, or it is a ghost in a sun. **Real clubs' badges are trademarks and are never used, offered or imitated** — which is also the better product, since a generator gives endless combinations where a list of borrowed badges gives a list. `35e-league.js` is the screen (`League.intro()`, `League.open()`, `League.boot()`, overlay `.lg-overlay`, `18-league.css`): create a league, invite by `?league=<invitation>`, join, then name the club and draw its crest and kit. Free offers six ready-made crests, custom opens every part, premium adds the metal; the client shows the prices (`crestTierCost`, `kitTierCost`) but **the server charges them** (`lg_set_identity`), only on a step up, and a step down is never refunded. An anonymous session is taken quietly, as the invitation rooms do. The league is remembered in `localStorage.goalasso.league.id` (only an invitation link opens it by itself; a manager who has one finds it behind its button, which then reads לליגה שלי, and on the beginner entry page under משחק רשת as המשך ליגת …); the board polls every 15 s. `tests/league-lobby.test.js` covers both on an in-memory fake of the SQL functions that answers as a server with only the first migration does, so it is also the test that the client still works against one.
- Shared league, the season (steps 3–7 of `docs/shared-league.md`; `supabase/migrations/20261115120000_shared_league_season.sql`, twin `supabase/install-league-2.sql` from `scripts/build-league-install.py`): the league is a full-screen app over the game (`.lg-overlay`, z-index 12000 so an invitation lands above the title screen; the penalty picture is raised over it with `.lg-overlay~.pg`) with tabs הליגה / הסגל / רכש / עסקאות / המועדון. State is one call, `lg_get`; `lgV2()` (the answer carries `me`) tells a server that has only the first migration, where the client keeps to lobby and identity. Files: `35e-league.js` shell, lobby, identity, board, one click listener dispatching `data-lg` actions (`LG_ACT`, `.quick` for actions with no server call); `35f-league-sim.js` the catalogue and the match; `35g-league-squad.js` squad, line-up, training, market, trades; `35h-league-match.js` the match screen and the penalty.
  - **Two phones play the same match** (`lgSimulate`): the server locks a fixture the first time either manager opens it (`lg_fixture_lock`: both squads as lists of keys with each player's training count, both setups, kits) and gives the seed only then. Each phone builds the same players from its own data — `lgCatalog()` keys them by the club's Hebrew name + `/` + the English name, as the price list does; rating is `euroRating` of the catalogue value and nothing else (a player has to be the same player for everybody who can buy him), age where missing and potential come from a generator seeded by the key, and **the id is a hash of the key** because `attrs(p)` derives a player's attributes from his id. The engine runs in `lgSandbox`: a throw-away `G` with nothing of the local career, `MP.capture` marking both clubs so both get `fixedLineup`, their own mentality and tactics, and a seeded generator installed as `Math.random` only while the engine runs. A club's id is fixed (`lgh`/`lga`) because `defaultTac` hashes it. `lgSimId()` = a build-time hash of the engine's source files (`__SIM_SRC__`, the list is `SIM_FILES` in `src/build.py`) + a hash of the catalogue; a phone on another fingerprint is told to update rather than left to disagree. `tests/league-sim.test.js`: forty matches identical in the full game with a career and the beginner page without one, the career untouched, and every catalogue price equal to the server's.
  - **A penalty** stops the simulation (`ui.pen` parks it); the phone shows the recording up to that minute, opens the penalty picture and sends its direction with `lg_pen`. The answer comes back only when both are in; an absent manager's direction and a per-kick number (`n`) are drawn by the server, so nothing about a penalty follows from the seed. The match is then run again from minute one with the longer log — a match is always a pure function of (lock, seed, penalty log), which is what makes it reopenable on any phone. `pcupResolve` decides the kick from the two directions and the taker's and keeper's skill.
  - **A result** is `lg_result(home, away, digest)`: counted when both phones send the same, dealt again from a new seed when they differ. `lg_round_close` (the host, or anyone after 48 h): one answer stands, nobody opened it → 0:0, opened and never answered → 0:3 against whoever locked it (`lock.by`).
  - **The market** lists the catalogue minus `taken`, client-side (instant search in Hebrew and English); `lg_buy` charges the pool's price. Faces in every league list are fetched only when the row comes into view (`lgFace` with `data-want`, `lgFacesWatch`): packs are one file per club, 100–400 KB, and a market screen would otherwise download fifteen megabytes. `lg_pool.face` (from `scripts/build-league-pool.py`, the same rule the build ships) lets "build me a squad" prefer a player the game has a photograph of. `supabase/install-league-pool.sql` is the list packed one text row per club (255 KB) so that it pastes into the SQL Editor; a club name may carry a slash of its own (בודה/גלימט), so a key is never split on `/`.
  - **The appointment** (`35i-league-kickoff.js`, `lg_kickoff`, `lg_tz`): the host may give a round a time. It is an appointment and not a gate — the match can be played before and after it. One instant (`lg_leagues.kickoff_at`, cleared when the round changes) that every phone shows on its own clock with a countdown (`#lg-count`, one ticker `lgKickTick`); each phone reports its IANA zone once (`lg_members.tz`), the picker shows the instant on everybody's clock, and an instant between midnight and seven (`LG_NIGHT`) for any manager is refused by the client (so the host sees whose night) and by the server (`night`). Five minutes before, `notify` fires once per appointment (`LG_WARNED` in localStorage) — **only while the page is open or in the background; there is no push server**, so the card also offers a calendar file (`lgIcs`, a VEVENT in UTC with `TRIGGER:-PT5M`) that rings with the game closed. `lgKickOK()` (the state carries `kickoff`) tells a server whose `install-league-2.sql` predates this. The ready-made crests are one list of `LG_CRESTS_ALL` 72 per club (`lgCrestChoices`: shapes take turns, the other parts come from separate bits of a hash, none twice); six are shown and one press opens them all.
