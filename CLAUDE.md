# GOALASSO · מאמן כדורגל

Hebrew (RTL), mobile-first football management game. Single-file web build.

## Layout
- `src/index.html` — document shell (doctype, meta, manifest/icons, markup) with `__CSS__` / `__JS__` placeholders.
- `src/styles/NN-*.css` — stylesheets, concatenated in file-name order. Later files override earlier ones: `07-theme-direction-a.css` is the current theme, `08-cinematic-lineup.css` the lineup screen (the stadium photo `assets/lineup-arena.*` with round portraits and a name plate — rating, name, fitness as the ring colour — placed by `pitchProject`/`ARENA` in `36-views.js`; `12-formation-board.css` keeps the beginner mode's formation board on `assets/lineup-reference-stadium.jpg`), `09-phone-readability.css` the mobile overrides, `10-market.css` the transfer-market search/filters.
- `src/js/NN-*.js` — the game, one shared script scope (no ES modules). Load order = numeric prefix: `01-data` → `02-util` → `03-players` → … → `36-views` → `36b-broadcast` … `36h-notify` → `37-live` → `38-boot`. Function declarations are hoisted, so views may call engine code; `const`/`let` must be declared in an earlier file than their first top-level use. Put new code in the file that owns the subject (engine in `07-engine.js`, money in `18-week-flow.js`, screens in `36-views.js`, persistence in `22-save.js`).
- `src/build.py` — `python3 -I src/build.py` → writes `ligat-haal-manager.html` at the repo root (concatenates the modules, embeds data, splash, logo and the portrait manifest). Placeholders `__CLUBS_JSON__`, `__EURO_JSON__`, `__DATA_META__`, `__SPLASH_IMG__`, `__LOGO_IMG__`, `__PLAYER_VISUALS__` are filled by the build.
- `data/*.json` — Israeli club squads; `data/euro/*.json` — European squads.
- `assets/` — media loaded at runtime by relative path (intro/signing videos, lineup stadium, newspaper photos, trophy moments). They must sit next to the built HTML.
- `tests/*.test.js` — jsdom suites (`npm install`, `npm run build`, `npm test`). A suite passes when its last line shows `errors []` / `errs []`. `idb-save.test.js` runs the IndexedDB path on `fake-indexeddb`; `window.ILM.ready` resolves after boot and `window.ILM.whenSaved()` after the pending write.
- Player portraits: `scripts/build-portraits.py` turns the verified source photos (`data/visuals/source-photos/`) into canonical 240×300 transparent WebP cut-outs in `assets/facepacks/` (schema 2) and records each result in `data/visuals/portrait-audit.json`; manual decisions live in `data/visuals/portrait-overrides.json`; `scripts/portrait-report.py` writes `docs/portrait-audit.md`. The game never crops faces at runtime (`portraitGroup` / `cinematicPlayerHTML` in `36-views.js`); anything not `ok` renders the designed club-kit monogram fallback. Never assign a face to a different player, and never match European players to Israeli faces by name.
- European portraits (real squads in `data/euro/`): `.github/workflows/fetch-portraits.yml` (manual; runs `scripts/fetch-commons-portraits.py`, identifies each player on Wikidata by exact name + club / birth year and downloads freely licensed Commons candidates with author/licence) → branch `portrait-sources`. Locally, `scripts/import-commons-portraits.py --sources <portrait-sources checkout> --clubs …` picks the first candidate the pipeline accepts in strict mode and writes `data/visuals/source-photos/eu-<club>.json` (git-ignored: the originals live on `portrait-sources`) + `data/visuals/euro-players.json` (identity, source, licence, credit, fallback reasons); then `build-portraits.py --only eu-<club>,…` and `--skin-only`. Files rejected on visual review go in `data/visuals/portrait-reject-files.json`. Files the strict checks refuse but a visual review accepts (frontal, single subject, verified identity) go in `data/visuals/portrait-accept-files.json`; a candidate with an attribution licence and no recorded author is never used. Faces resolve by club + English name only; credits ship in each pack and show on the player profile and under מידע → תמונות שחקנים.
- Real squads from Wikipedia (clubs in `data/config/world-clubs-wiki.json`): `.github/workflows/fetch-squads.yml` (manual; `scripts/fetch-wikidata-squads.py`: the article's current-squad templates, else the club's squad template with positions from Wikidata, Hebrew Wikipedia for the Leumit clubs; a player "on loan from" another club is a squad member) → branch `squad-sources` (`squads/<key>.json`, `_debug/` dumps for pages that did not parse). Locally `scripts/import-squads.py --sources <checkout>/squads --clubs …` writes `data/euro/<key>.json` (one factor per squad puts its best-14 rating on the club's strength + 1) and lists the players as unresolved in `euro-players.json`; `--merge` adds players a newer fetch lists (nobody is removed), `--sync-identities` afterwards, `--rescale` re-applies the value rule. Portrait candidates for new or changed squads are fetched from a work branch (`ref=squads-wip`) so nothing half-done deploys. Only one portrait import may run at a time (it rewrites `euro-players.json` as a whole).
- Real players only: the config groups are `world` (market clubs), `euro` (European opponents of `EURO_CLUBS`) and `leumit`; a club with no squad on Wikipedia is removed from the game rather than shown with invented players (Young Africans, Petrocub). `inventedPlayer(p)` (no English name, no Israeli identity) marks generator players: they are never listed on the market, in the search or as free agents, the free-agent list starts empty, and real squads are never padded. Invented players remain only where the game needs bodies: academy prospects, season-end top-ups of AI clubs and clubs promoted from Liga Alef. Hebrew spellings for second-tier players that the sources give in Latin letters live in `data/config/leumit-names-he.json` (transliterations; `import-squads.py --clubs all --names`). Save v12 (`migrateRealOnly`) applies all of this to existing careers.
- First person: the 3D highlights have two extra cameras (`עיני הבועט`, `עיני השוער` in `assets/demo3d/live.js`: the camera sits at the player's eyes, his own body hidden). Coach's-eye video clips (press conference, tunnel, dressing room, trophy…) are described in `data/config/video-prompts.json` and generated by `.github/workflows/grok-video.yml` (manual; `scripts/grok-video.py`, xAI video API, repository secret `XAI_API_KEY`) onto the `video-sources` branch for review; no real people, badges or readable text in the prompts.
- Portrait review: `scripts/check-portraits.py [--sheets DIR]` measures every shipped cut-out (frame, eye line, face size, hair against the top edge, sides, opacity, sharpness). The import (`import-commons-portraits.py`) writes the accepted cut-out into the pack itself (cache in `<sources>/.import-built`), so `build-portraits.py --only …` is only needed for faces decided by an older cache. Round avatars (`.rt-face`, `.bc-face`) are framed by `faceFrameStyle(p)`: the window starts 12 px above the player's own hair line (`PLAYER_VISUALS.faces[].top`, from the audit's `hairTop`), never lower than 20 px. A cut-out without shoulders (`bust:0`) gets a drawn soft neck and collar in `portraitGroup`.
- Broadcast package (`36b-broadcast.js`, `14-broadcast.css`; presentation only, reads `M` and its events): `#bcLayer` inside the arena (a flat strip when match graphics are off). `bcEvent` queues one plate per key event (goal, card, substitution, injury, big save) with the player's face; `bcScore` pulses the score bug and marks sent-off players; `bcSlate(M,h,a,'half'|'full')` is the statistics board at the breaks (score, scorers, possession, shots, xG, man of the match). The app header (`#top`) is hidden while the live screen is up; `render()` brings it back. `tests/broadcast.test.js` covers it.
- World transfer market (`11-market.js`, `viewWorld`; Israel tab `viewMarket` in `36-views.js`): clubs with data in `data/euro` show their full squad (`fillRealWorldSquad`, idempotent: a player is recognised by English name + origin club `p.from`, so re-valued data never duplicates him; `WORLD_SQUAD_V` marks the data generation, and a squad from an older generation that sits 3+ points under the club's strength is lifted back to it; run by save migrations v9 and v11); real squads are never padded with invented players; the 11 most valuable players are listed as in the squad but not for sale (`p.nfs`): talks open only with an exceptional offer (asking price ×2.4 at tier-1 clubs, ×1.9 elsewhere, no haggling below it, 2 rounds of patience). Every market club has a real squad (the generated 7-player list is only the fallback path for a club whose data is missing). "ליגיונרים ישראלים" = real players whose data nationality is Israel at clubs outside Israel. Name search gives live suggestions from 2 letters (Hebrew/English, accents and Hebrew final letters ignored) across Israel and all world leagues. `tests/world-market.test.js` covers it; `.github/workflows/live-check.yml` (manual) runs `scripts/live-market-check.js` on the deployed site at iPhone size and pushes screenshots + report.json to the `live-check` branch; the report's `play` section covers live play on the deployed build (shout bar, one penalty we kick and one we keep goal for, both through the overlay, with the view that drew them, career card, a quick-tournament draft and the return to the career); the script owns every penalty of its match, so a penalty the engine awards by itself is decided automatically there, and it reports `gpu3d` (would the game pick the 3D view on that browser by itself) and `slow3d` (the frame-rate verdict after the first kick). The `beginner` section opens `beginner.html` beside the page: score numbers on their own team's side, the carrier's name on the pitch, ratings of both sides in the result dialog. Each build carries `<meta name="goalasso-build">` (content hash) so the check can tell which build is live.
- Match engine (`07-engine.js`): three units per side from the XI (`unitStrength`: gk/def/mid/att by slot, roles blur them; captain, boosts, chemistry, mental programme and the training plan's `trainBonus` apply to all units). `expGoals` = attack vs the opposing defence on a convex curve (~0.08 goals per rating point, capped), scaled by midfield edge, plus home advantage, mentality, `tacticAdj`, and an 8-minute momentum after goals. Each minute a side may create a chance (rate ∝ expected goals); `chanceSpot` by style gives a location and real xG; the shooter's finishing against the keeper decides goal/save/post/off, normalised per style so goals average expGoals. In-match fatigue uses `liveEnergy` (press/tempo burn energy; `minuteFatigue` deducts rating below 82 energy; tired players get injured more; subs come on fresh). AI clubs get roles from attributes and a mentality from the strength gap (`aiPrepare`) and switch by score from 45'. `scripts/sim-balance.js [rounds]` prints goals/match, result split and upset rate by gap; `tests/engine.test.js` guards all of it (stronger side by 7+ points wins ≥55%, loses ≤22%).
- Sound (`17-cloud-sim-sound.js`): `AUD`/`audBus()` is a WebAudio mixer with crowd / sfx / music gains (`G.vol`, sliders in the settings card, `G.sound=false` mutes all). Recorded cues live in `assets/audio/*.opus` with an AAC twin (`*.m4a`, tried when Opus fails to decode, i.e. Safari) (`AUDIO_FILES`, credits in `assets/audio/credits.json`), lazy-decoded after the first tap (`audPreload` in boot). `CROWD` drives the match: `kickoff(att)` plays the bed as overlapping 24 s segments with a 3 s crossfade (never a loop point, which iOS cut audibly) at a volume from attendance, `chance`/`goal` duck the bed and recover, `song` from 80' when leading, `halftime`/`pause`/`resume`, `end()` fades everything (no cue is ever cut; `render()` of any other screen fades the stadium out). The synthesized `SFX` tones remain the fallback when a file is missing.
- Multiplayer v1 (`src/js/35b-multiplayer.js`, schema `supabase/migrations/20261023120000_multiplayer.sql`): two human managers in one league, host-authoritative. The host's phone simulates: every week each manager runs his club and presses "מוכן" (`mpReady` → `mp_ready` with the whitelisted commands of `mpCommandsFor`: formation, lineup, captain, mentality, tactics, plan, roles, ticket); when both are ready, or the turn timer (`turn_min`) has expired and the host is ready, `mpHostSimulate` applies the guest's commands (`mpApplyCommands`), plays the whole week instantly (`MP.capture` marks both human clubs so `isHumanClub` gives them fixed lineups, their own roles/mentality and chemistry; `runInstant` pushes their matches to `MP.captured`), records those matches (`mpRecord`: events, score, stats, man of the match) in `G.mp.lastWeek` and commits gzip+base64 state with `mp_commit` (optimistic revision). Guests load each new revision (`mpLoadRevision`, keeps `G.me`/`G.mp`) and both phones watch their own recorded matches through the live screen in playback mode (`mpPlayback` → `M.playback`; `stepMinute` only replays events via `mpPlaybackStep`; no subs, no settle, `MP.watching` blocks `render()`). Guest + invite code / `?join=CODE` link, anonymous auth, Realtime on `mp_leagues`/`mp_members` plus a 25 s poll, presence via `last_seen`. No onboarding ceremony and no transfer market in multiplayer (`mpNoMarketHTML`). Config: `__SUPABASE__` is filled by the build from `SUPABASE_URL` / `SUPABASE_PUBLISHABLE_KEY` (environment, `.env`, or the Pages workflow secrets), `localStorage.goalasso_supabase` overrides at runtime, `window.__mpClientFactory` injects a client (tests). `tests/multiplayer.test.js` runs host + guest jsdom windows on an in-memory fake of the SQL functions. `.env.example` lists the only public values the client may use.

- Live play (`37-live.js`, `36e-shouts.js`, `36f-penalty.js`, `15-live-play.css`; `tests/engage.test.js`):
  - Speed buttons `תקציר` / ×1 / ×2 / ×4, remembered in `G.spx`. Highlights (`תקציר`, `hl`) runs quiet minutes at 230 ms and holds the clock on a minute with a key event (`hlHold`), so a match takes about 40 s. ×1 is `G.speed` seconds (90 by default).
  - Touchline shouts: `M.voice` fills by 100/12 per match minute; a shout (`shoutStart(M,club,k)`, `k` = press | all | calm | hold) lasts `SHOUT_MIN` minutes. The effect is in `07-engine.js`: `shoutAdj` adds expected goals per 90 to both sides and to possession, `shoutTick` burns or restores energy through `M.burn` (read by `liveEnergy`), calm halves cards and cancels the opponent's momentum. Only the live screen starts a shout: simulated matches, AI clubs and multiplayer playback are untouched, so the balance tests are unaffected.
  - Penalties the manager takes himself: `stepMinute(M,ui)`; when `ui.pen()` is true and the user's club is involved, `penAward` parks the penalty in `M.pendingPen` and the live screen reports the outcome with `penResolve(M,club,taker,'goal'|'miss',how)`. A parked penalty nobody answered is decided by the next `stepMinute`. For our club the user kicks (press, steer the swaying sight, release), against it he keeps goal (swipe to the side; before the kick is a guess, inside `penReactMs` after it is a read). Rules are pure functions (`penFrame`, `penSaveP`, `penKickOutcome`, `penKeepOutcome`, `penShootoutDone`). A level knockout tie (`cup`, a final, a second leg level on aggregate, `ctx.ko`) opens `penShootout`, which sets `M.pens` and `M.penScore`. `G.penGame===false` (settings) keeps everything automatic; the legacy live suites set it. The picture is `assets/demo3d/penalty.js` (the stadium of the 3D highlights, one view reused for a whole shoot-out) with an SVG fallback `penStage2d` (no WebGL, reduced motion, jsdom); both implement `toScreen/fromScreen/shoot/runUp/incoming/gloves`. Both teams wear the colours of the match (`penKits` → `matchColors`, so a clash moves the away side to its second kit) and the keeper a colour neither side does. The 3D view is only for a browser with a graphics chip (`pen3dOK` asks for WebGL with `failIfMajorPerformanceCaveat`; `G.pen3d===true` takes it anyway, which the live check uses on its software-rendered runner, `G.pen3d===false` never does); a view that draws under ten frames a second reports `onSlow` and later kicks of the session use the flat picture (`pen3dBad`). The kick's ten seconds run on `penClock`, which counts shown frames only (a slow frame or a tab in the background adds 0.1 s at most).
  - Haptics: `buzz(kind)`, off with `G.haptic===false`.
  - The live picture (`tests/live-picture.test.js`): a score between two teams that stand side by side is `scoreSides(gh,ga)` (`02-util.js`, `.sides`): home number first, so beside the home side on the right; never one left-to-right text "1 : 0" (prose such as "ב"ש 1:0 מכבי" keeps the usual notation). In open play the ball has an owner on both 2D pitches (`carryMinute`/`carryFrame` in `14-arena-svg.js`, shared with `15-arena-pixi.js`): it is played to one outfield player of the side in possession, stays at his feet until the next pass (at least `CARRY_MIN` ms, so the name is readable at ×4) and his name is shown (`st.car`, `st.carNow`, SVG `st.carLab`); shots, corners, celebrations and replays have no carrier. The picture takes the same two `Math.random` numbers per minute as before, the rest comes from its own generator (`st.rs`). SVG name labels keep one size on screen (`LAB_FS`). In the 3D highlights `eventFrame` returns `holder` (the passer of the final ball when `clip.assist` is known, then the shooter, the keeper after a save) and `live.js` places `.m3-tag` above him. The foreign-player limit also holds for substitutions (`subBreaksForeign` in `doSub`/`autoSub`; `foreignLimited` = clubs of the Israeli leagues, not the quick tournament): a foreigner may come on beyond `MAX_FOREIGN_XI` only for a foreigner. The beginner result dialog shows, under the score, who scored and assisted and who was carded (`BmatchFactsHTML`) and the ratings of both sides (`BratingsHTML`, from `matchRatings`). The beginner mode lists real free agents only (generated ones are dropped on create and on load; the "invented" label follows `inventedPlayer`).
- Between matches (`36c-engage.js`, `36d-career.js`, `16-engage.css`):
  - Career book `G.car` (save v13, `carBackfill` for older careers): counters `n`, streaks `st`, records `rec`, trophies `tr`, achievements `ach`, `fresh` (unlocked, not shown). Fed by `carAfterMatch` (from `settle`, never friendlies), `carTrophy` (from `recordMoment` and the season end), `carSeasonEnd`, `carSigning`, `carWeekly`. Achievements are rows in `achDefs()` (`[id, name, text, category, target, value, stars]`); stars give the manager level (`carLevel`). Screen: `viewCareer` (`G.view='career'`), home card `careerCardHTML`.
  - `nextHooks()` lists facts about the coming week (derby, top of the table, streak, a player one goal from a round number, an achievement almost done); shown on the home card and in `nextUpModal` after a live match.
  - The envelope: `surpriseRoll(M)` runs once after each competitive match (`afterMyMatch`); about one match in three, never twice in a row, never more than four without. It applies a small real effect at once (academy jump, a free scout report on a real affordable player, sponsor bonus, fans, form, recovery, morale, board) and records it in `G.env` and the news; `envelopeOpen` only reveals it (after a live match through `postMatchFlow`, otherwise through `maybeShowQueued`).
- Quick tournament (`36g-blitz.js`): draft one of three real players for each position (`blitzPool`, rated like `rawSquad`), links between team-mates of the same club or country give up to +3 (`G.mentalBoost`), then four knockout rounds against real clubs at rising strength (`BLITZ_ROUNDS`), played on the normal live screen (`ctx.ko`, highlights by default). It runs on a throw-away state: `blitzSandbox` swaps `G` for a `newGame()` state flagged `G.blitz`, the career waits in `BLITZ.career`, and `SANDBOX` makes `save`, `saveSync` (through `save`) and `emergencyFlush` no-ops; `blitzExit` restores `G` and `uid`. Only the record (`BLITZ_KEY`) and the current run (`BLITZ_RUN`) are kept, in localStorage. Never call `settle`, `afterMyMatch` or `finishWeek` in the sandbox.
- Notifications (`36h-notify.js`, `assets/sw.js`): opt-in per device (`localStorage.goalasso_notify`), only while the game is open in the background, only for real events of network play (`mpNotifyReady`, `roomNotify`). The service worker shows the notification and focuses the game; it caches nothing. There is no push server.

## Rules
- Keep saves backward compatible: `SAVE_VERSION` + `MIGRATIONS` in `src/js/22-save.js`. Careers persist in IndexedDB (gzip, one record per slot + `backup:N`, career id + revision with compare-and-set); browsers without IndexedDB and the jsdom suites use the legacy localStorage layout. `save()`/`load()`/`installCareer()` return a Promise in IndexedDB mode and a boolean otherwise — wrap with `Promise.resolve(...)` when the outcome matters.
- UI text in natural Hebrew; isolate numbers/Latin with `<bdi>`.
- Never put a Supabase service_role/secret key in the repo or the client.
- Multiplayer: keep it host-authoritative and gated on `G.mp`; guests never write league state, only their member row. No voice/WebRTC yet (planned: STUN only).
- Tests use `window.__ilmNoSplash=1` (skip intro) and `window.__ilmUnlock=1` (all clubs selectable).

## Deploy
- Claude artifact: publish `ligat-haal-manager.html` with every file in `assets/` as supporting files.
- GitHub Pages: `.github/workflows/pages.yml` builds and deploys on push to `main` (enable Pages → Source: GitHub Actions).

- Invitation friendlies: `35c-network-rooms.js` is the production entry in beginner and Pro, using existing room RPCs and email auth. See `docs/network-friendlies.md`. Legacy league support remains for existing `G.mp` saves. Build config placeholder is `__SUPABASE_BUILD__`; the public fallback is `data/config/multiplayer-public.json`.
